# Forensic Audit: HamaraGhar AIML & Floor-Plan Architecture

**Date:** September 2026  
**Auditor:** Antigravity AI Engineering Team  
**Scope:** Forensic repository inspection of all ML subsystems, procedural generators, datasets, models, APIs, and UI layers prior to the real-dataset floor-plan ML transformation.

---

## Executive Summary of Findings

1. **Procedural Geometry vs ML**: The current floor-plan generator is entirely deterministic, rule-based procedural geometry. No machine learning model generates room coordinates.
2. **Existing Real ML Model**: `property_price_regressor_v1.joblib` is genuinely trained on a real Kaggle dataset (29,451 residential property transactions across India) with $R^2=0.8492$ for property market valuation.
3. **Existing Floor-Plan ML Status**: Floor-plan models currently in the repo (`layout_quality_ranker_v1.joblib`, `archetype_classifier_v1.joblib`) were trained on **synthetic data** generated via random beta/uniform distributions in `generate_datasets.py` and `train_layout_ranker.py`.
4. **Real Floor-Plan Dataset Status**: **NO real architectural floor-plan dataset currently exists in the repository.** The only real dataset is `kaggle_house_prices.csv` (property prices, not layout geometry).
5. **Civil Engineering Rules**: CPWD DSR 2024 construction cost estimation is purely deterministic quantity takeoff and correctly isolated from ML market valuation.
6. **Structural Verification**: NBC 2016 verification (`verify_nbc_compliance`) acts as a hard deterministic constraint gate checking setbacks, pairwise room collision ($R_i \cap R_j = \emptyset$), and minimum room sizes.

Floor Plan Generation** | How is the floor plan currently generated? | Via `generate_deterministic_floor_plan(config, floor, variant)` in `app.py` (lines 99–380) and `PlanGenerator.generate()` in `plan-generator.js`. It computes setback boundaries and places room boxes using fixed proportional subdivisions. |
| **2. Room Geometry** | Which functions create room geometry? | `generate_deterministic_floor_plan()` creates the list of room dictionaries (`x`, `y`, `width`, `height`, `id`, `name`, `type`, `zone`, `color`, `floorName`). |

Checks front ($\ge 10\%$, $\ge 3$ft), rear ($\ge 8\%$, $\ge 2.5$ft), side ($\ge 8\%$, $\ge 2$ft) setbacks; room envelope containment; pairwise collision test ($R_i \cap R_j = \emptyset$ with $0.3$ft wall tolerance); and NBC Part 3 Table 1 minimum habitable room areas. |

## 3. Structural Gaps & Required Upgrades for Honest AIML

1. **Eliminate Synthetic Floor-Plan Data**:
   Replace synthetic data with a documented, legitimate real floor-plan dataset (e.g. CubiCasa5K open benchmark or structured extracts thereof).
2. **Dedicated Floor-Plan ML Module (`ml/floorplan/`)**:
   Establish a clean, reproducible architecture:
   - `ml/floorplan/dataset.py` (Dataset downloader/loader & provenance documentation)
   - `ml/floorplan/preprocessing.py` (Extracts real room polygons, counts, areas, and spatial relationships)
   - `ml/floorplan/features.py` (Vectorizes real architectural features without data leakage)
   - `ml/floorplan/train.py` (Trains model on real dataset with train/val/test splits)
   - `ml/floorplan/evaluate.py` (Evaluates holdout performance with actual task metrics)
   - `ml/floorplan/inference.py` (Loads production model and provides sub-millisecond scoring)
   - `ml/floorplan/model.py` (Model definitions and baselines)
   - `ml/floorplan/README.md` (Dataset source, licensing CC BY 4.0, download instructions, schema)
3. **Legitimate ML Task Definition**:
   Train on empirical real floor-plan patterns:
   - E.g. **Architectural Layout Typology & Spatial Viability Classifier / Regressor** or **Room Adjacency & Spatial Flow Predictor**, grounded strictly in what the real dataset provides.
4. **Project-Specific Procedural Diversity**:
   Ensure different inputs (Plot A: 30x40 2BHK vs Plot B: 40x60 4BHK with parking/pooja) produce genuinely distinct topologies, room counts, and aspect ratios rather than scaled copies.
5. **Deterministic Hybrid Pipeline**:
   Same input + model version = deterministic candidate generation $\rightarrow$ ML feature extraction $\rightarrow$ ML scoring $\rightarrow$ NBC clearance gate (rejects invalid candidates) $\rightarrow$ Ranked valid candidates (Rank #1 recommended).
6. **Canonical Geometry for 2D and 3D**:
   Ensure the 2D CAD renderer, 3D Elevation Studio, CPWD BoQ engine, and ML feature extractor all consume the same canonical geometry specification.
7. **Transparent UI & Documentation**:
   Clear separation of:
   - GenAI: Requirement parsing
   - Procedural Candidate Generator: Geometry generation
   - Real ML Model: Learned spatial intelligence
   - NBC 2016: Hard engineering validation
   - CPWD DSR 2024: Construction cost takeoff
   - Kaggle ML Model: Property market valuation
